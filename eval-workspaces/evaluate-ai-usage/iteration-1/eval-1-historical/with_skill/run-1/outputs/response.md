1. **Front-load big features with a mini-spec, not a sentence.** For anything that's going to be >50 turns of work (you can usually tell — multi-layer changes, new feature flags, payment/eligibility logic), open with: scope boundary, file/area refs from a quick grep, acceptance criteria, and the one wrong direction you already rejected. **Why it matters (learning + throughput):** the BMO conversation lost ~6 turns to clarification round-trips that 3 minutes of upfront writing would have eliminated, and the conversation drifted into a "PM draft PR" you had to explicitly disavow at msg [251] *after* Claude had referenced it. Example moment: `9602e9b6` msg [26] is the canonical case. The retroactive answers you gave at [301] should have been in [26].

2. **Make `/superpowers:brainstorming` the default for any feature touching ≥2 layers or files.** You already trust it for ambiguous copy work — extend the trigger. **Why it matters (learning):** the Peacock gate ended up exactly where the brainstorm would have placed it (activate-click only, not flyout render), but you got there via msg [79] pushback instead of upfront design. Three turns of brainstorm replaces six turns of redirect.

3. **Add a one-line system reminder that forces parallel tool batching and proactive skill invocation.** Zero parallel batches across ~1,090 turns is not a Joyce problem — it's a Claude-defaults problem in your environment. A short user-memory rule like *"when you have ≥2 independent reads, searches, or subagents, batch them in one turn; when a task matches a known skill trigger, invoke it via Skill tool without waiting to be asked"* would change the loop on every session. **Why it matters (throughput + leverage):** even a modest 30% rate of parallelization on a 200-turn feature is 60 fewer round-trips. Compounded over your weekly volume that's hours.
